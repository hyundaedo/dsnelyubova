# DNS. Базовая информация

<div markdown>

## Что такое DNS

**DNS** (Domain Name System) — система, которая хранит данные о доменных именах, в том числе их IP-адреса. Она работает как адресная книга интернета: по имени сайта (например, `example.com`) находит его IP-адрес (например, `93.184.216.34`).

Зачем это нужно: пользователь вводит в браузере понятные ему имена сайтов, а устройства в сети находят друг друга только по IP-адресам. Перед каждым подключением к сайту устройство отправляет **DNS-запрос** — вопрос «какой IP-адрес у этого домена?» — и получает ответ от DNS-сервера.

!!! note ""
    DNS хранит не только IP-адреса: у него есть и другие функции. Подробнее о них см. в статье «[DNS-записи](link)».

## Как работает DNS

Весь путь занимает доли секунды. Чтобы не повторять его каждый раз, ответы временно сохраняются в **кэше**.

**Шаг 1. Проверка кэша на устройстве**  
Когда пользователь вводит доменное имя и нажимает Enter, браузер проверяет кэш на устройстве:

- совпадение найдено — браузер переходит на сайт по IP-адресу; 
- совпадение не найдено — браузер отправляет запрос рекурсивному DNS-серверу.

**Шаг 2. [Рекурсивный сервер (резолвер)](#resolver)**  

Обычно это DNS-сервер провайдера, публичный DNS-сервер или DNS-сервер VPN. Запрос может сначала попасть на роутер, который передаст его дальше. Рекурсивный DNS-сервер проверяет, есть ли ответ в его кэше:

- совпадение найдено — резолвер возвращает IP-адрес браузеру, и тот переходит по нему;
- не найдено — резолвер проходит цепочку серверов (шаги 3–5), чтобы найти IP-адрес.

**Шаг 3. Корневой сервер (root-сервер)**  
Root-сервер не знает IP-адресов сайтов, но он знает, какие серверы отвечают за доменные зоны верхнего уровня (`.com`, `.org`, `.ru`). Он указывает адрес нужного TLD-сервера. Резолвер обращается к TLD-серверу.

**Шаг 4. Сервер доменной зоны (TLD-сервер)**  
TLD-сервер (Top Level Domain) — домен верхнего уровня, то есть последняя часть имени: `.com`, `.org`, `.ru`. TLD-сервер знает, какой сервер хранит записи конкретного домена, и указывает его адрес. Резолвер обращается к этому серверу.  

**Шаг 5. Авторитативный DNS-сервер домена**  

Хранит актуальные записи домена, внесённые его владельцем. Для сайта это запись с IP-адресом.

**Шаг 6. IP-адрес и кэш**  
Если авторитативный DNS-сервер домена вернул IP-адрес сайта, резолвер записывает его в кэш и передаёт браузеру. Браузер **устанавливает соединение** с сайтом по этому IP-адресу.  

!!! warning ""
    IP-адрес может быть не найден по нескольким причинам:  
    
    - опечатка в доменном имени;
    - домен не существует или не оплачен владельцем;
    - ошибка в настройках DNS-записей, авторитативный сервер не содержит нужной записи для этого домена;
    - DNS-сервер недоступен или не отвечает.

    В таком случае пользователь видит ошибку, например «Сайт не найден».


## Типы DNS-серверов
DNS-серверы различаются по двум признакам: **какую роль** они выполняют и **кто ими управляет**. Один и тот же сервер может подходить под несколько описаний.

**По роли**

| Тип DNS-сервера | Что делает | Где встречается |
| :- | :- | :- |
| Авторитативный (Authoritative) | Хранит записи конкретного домена и даёт окончательный ответ. Сам ничего не ищет в других местах, а отдаёт то, что указал владелец домена | Хостинг-провайдеры, регистраторы доменов, DNS-сервисы владельцев сайтов |
| <a id="resolver"></a> Рекурсивный (Recursive), резолвер | Принимает запрос от устройства. Если ответа нет в кэше, сам обращается к корневому, TLD- и авторитативному серверам, пока не получит IP-адрес | Провайдеры, публичные DNS, VPN-сервисы, роутеры |
| Корневой (Root) и TLD-сервер | Указывают, где искать следующий сервер в цепочке. Адресов сайтов не хранят | Операторы корневых серверов и доменных зон |

!!! note ""
    **Кэширующий DNS-сервер** — это не отдельный тип, а функция: сохранять полученные ответы на время TTL (Time To Live — время жизни записи). Она есть у большинства рекурсивных серверов, у роутеров и операционных систем. Кэш ускоряет загрузку сайтов и снижает нагрузку на DNS-серверы, но до конца TTL может выдавать устаревший ответ.

**По принадлежности**

| Тип DNS-сервера | Описание | Примеры |
| :- | :- | :- |
| Провайдерский | Рекурсивный сервер вашего интернет-провайдера. Используется по умолчанию | DNS Ростелеком, МТС и других провайдеров |
| Локальный (Local) | Работает внутри домашней или рабочей сети либо на самом устройстве. Может хранить ответы в кэше и пересылать остальные запросы на вышестоящий сервер | Wi-Fi роутер, служба DNS-клиент в операционной системе |
| [Публичный](#публичные-dns-серверы) (Public) | Рекурсивный сервер, доступный любому пользователю интернета | Google, Cloudflare, Quad9 |


## **Публичные DNS-серверы**  
По умолчанию устройство пользователя использует DNS-серверы провайдера, которые могут работать медленно или нестабильно. Публичные DNS-серверы позволяют:

- ускорить загрузку сайтов;
- повысить безопасность;
- обойти блокировку провайдера, если она сделана на уровне DNS;
- снизить зависимость от провайдера.

| Провайдер | Основной IP | Дополнительный IP | Особенность |
| :--- | :--- | :--- | :--- |
| Google | `8.8.8.8` | `8.8.4.4` | Высокая скорость, стабильность, серверы по всему миру |
| Cloudflare | `1.1.1.1` | `1.0.0.1` | Упор на приватность, заявляет о минимальном хранении данных о запросах |
| OpenDNS | `208.67.222.222` | `208.67.220.220` | Родительский контроль и защита от фишинга |
| Яндекс DNS | `77.88.8.8` | `77.88.8.1` | Оптимизирован для пользователей из России |
| Quad9 | `9.9.9.9` | `149.112.112.112` | Блокирует известные вредоносные домены |
| AdGuard DNS | `94.140.14.14` | `94.140.15.15` | Блокирует рекламу и трекеры на уровне DNS |

!!! note ""
    Дополнительный IP-адрес используется, если основной недоступен.

!!! warning ""
     При использовании VPN менять DNS-серверы в настройках операционной системы обычно не нужно. Запросы должны идти на DNS-сервер VPN-клиента (подробнее см. в разделе [«Как связаны DNS и VPN»](#как-связаны-dns-и-vpn)).

## Как связаны DNS и VPN

VPN шифрует трафик и скрывает настоящий IP-адрес. Посещая сайты, пользователь всё равно отправляет DNS-запросы, поэтому важно, **куда** он уходит.

Обычно VPN-клиент использует один из вариантов:  

1. DNS-сервер VPN — [резолвер](#resolver) на стороне VPN-сервиса.
2. Публичный DNS-сервер — например, `1.1.1.1`.
3. DNS-серверы устройства пользователя — этот вариант чаще всего приводит к [утечке DNS](#утечка-dns).



|  | DNS-запрос внутри VPN-туннеля | DNS-запрос вне VPN-туннеля |
| :- | :- | :- |
| Куда уходит | На DNS-сервер, который использует VPN | На DNS-сервер провайдера или роутера |
| Что видит провайдер | Только зашифрованный трафик до VPN-сервера | Список доменов, которые запрашивает пользователь|
| Итог | Так и должно быть | Утечка DNS |

### Утечка DNS  

Утечка DNS возникает, когда VPN включён, но DNS-запросы уходят вне VPN-туннеля. Например, так провайдер всё равно может видеть, какие сайты посещает пользователь.

Для проверки на утечку DNS нужно:

1. Выключить VPN и зайти на любой сервис проверки утечек DNS.
2. Зафиксировать, какие DNS-серверы и страну показывает сервис.
3. Включить VPN и снова сделать проверку: 
    - видны провайдер или страна пользователя — утечка есть;
    - видны VPN-сервис или другая страна — утечки нет.
