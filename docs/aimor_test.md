## **Что такое DNS**

Когда мы хотим перейти на какой-то сайт, то обычно в адресной строке пишем его доменное имя (например, `example.com`). Но в сети компьютеры находят друг друга иначе — по IP-адресам (например, `93.184.216.34`).  
DNS нужен, чтобы определить, какому IP-адресу соответствует доменное имя.  

DNS (Domain Name System) — распределённая система, хранящая записи о соответствии доменных имён и IP-адресов. «Адресная книга» для сайтов.  

Когда пользователь вводит доменное имя сайта в браузере, DNS помогает найти его IP-адрес. Но это не единственная его функция (подробнее см. в статье «[DNS-записи](link)»).

## **Какие бывают DNS-серверы**  
DNS-серверы можно разделить на типы в зависимости от их роли в сети.  

| Тип DNS-сервера | Роль | Использование |
| :- | :- | :- |
| Авторитативный | Хранит актуальные записи о конкретном домене и отвечает за них. Он не ищет информацию в других местах, а просто отдает то, что у него прописано владельцем домена | Владельцы сайтов, хостинг-провайдеры |
| Рекурсивный | Принимает запрос от пользователя. Если не знает ответа, самостоятельно опрашивает другие серверы (корневые, авторитативные), пока не найдет нужный IP-адрес | Провайдеры интернета, публичные сервисы (Google, Cloudflare) |
| Кэширующий | Cохраняет ответы предыдущих запросов на определенное время (TTL). Это ускоряет загрузку сайтов и снижает нагрузку на сеть. Рекурсивные серверы обычно работают с кэшем | Домашние роутеры, локальные сети, провайдеры |
| Локальный  | Сервер, который работает в пределах вашей домашней сети или устройства. Он может кэшировать запросы или перенаправлять их на вышестоящий (провайдерский) сервер. | Ваш Wi-Fi роутер, служба DNS-клиент в операционной системе. |
| [Публичный](#публичные-dns-серверы)  | Доступен для любого пользователя интернета. Часто предлагают повышенную скорость, безопасность и защиту от цензуры. | Google DNS, Cloudflare, Quad9 |

## **Как работает DNS**

**Шаг 1. Проверка кэша**  
Когда вы ввели имя сайта и нажали Enter, браузер проверяет кэш на устройстве. Если соответствие с IP-адресом найдено, браузер «подменяет» имя сайта на IP и переходит по этому адресу.  
Если соответствий не найдено, браузер обращается к resolver-серверу.

**Шаг 2. Resolver-сервер**  
Resolver-сервер — это ::%%%?: . Обычно он находится у вашего интернет-провайдера.

Resolver-сервер сопоставляет имя сайта со своим кэшем. Если совпадение найдено, то браузер переходит по нужному IP. Если не найдено — resolver шлёт запрос к root-серверу.

**Шаг 3. Root-сервер**  
Root-сервер —   . Он отдаёт не IP сайта, а адрес TLD-сервера, к которому нужно обратиться для получения нужного IP. Resolver обращается к TLD-серверу.

**Шаг 4. TLD-сервер** 
TLD-сервер (Top Level Domain) — сервер верхнего уровня, 


| С привязкой по странам (ccTLD) | .ru, .by, .us |
| :- | :- |
| Без привязки по странам (gTLD) | .edu, .ai, .com |

TLD-сервер определяет доменную зону сайта и говорит, к какому серверу авторитативных имён нужно обратиться. Resolver обращается к этому серверу.

**Шаг 5. IP и кэш**  
Если сервер авторитативных имён сообщил IP-адрес сайта, resolver запишет его в кэш

## **Как связаны DNS и VPN**

!!! note ""
    Обычно VPN-клиент использует один из вариантов:  

    1. DNS сервиса VPN — [рекурсивный](#какие-бывают-dns-серверы) сервер на стороне VPN.
    2. Публичный DNS-сервер — например, `1.1.1.1`.
    3. DNS системы пользователя — этот вариант чаще всего приводит к [утечке](#утечка-dns).

VPN шифрует трафик и скрывает ваш настоящий IP-адрес. Посещая сайты, вы всё равно делаете запросы к DNS-серверам, поэтому важно, **куда** уходит такой запрос.

|  | DNS-запрос внутри VPN-туннеля | DNS-запрос вне VPN-туннеля |
| :- | :- | :- |
| Куда уходит | На DNS-сервер, который использует VPN | На DNS-сервер провайдера или роутера |
| Что видит провайдер | Только зашифрованный трафик до VPN-сервера | Список доменов, которые запрашивает пользователь — утечка DNS|

### Утечка DNS  

Утечка DNS возникает, когда VPN включён, но DNS-запросы всё равно уходят к провайдеру.  

Для проверки утечки DNS нужно:

1. Выключить VPN и зайти на любой сервис проверки утечек DNS.
2. Зафиксировать, какие серверы показывает сервис.
3. Включить VPN и снова сделать проверку: серверы те же — утечка есть, другие — утечки нет.
